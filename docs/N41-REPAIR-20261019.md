# N41 — 人工字幕 cue 翻页契约修复记录（2026-10-19）

本文件记录 `docs/N41-ROOT-CAUSE-20261019.md` 之后实施的根修。范围是当前工作树
`dev/1.5.4-deepseek`；没有签名、安装、推送或发布。

## 0. 修复摘要

| 问题 | 修复后的权威 |
|---|---|
| 人工 cue 被模型 event 拆成多页 | `Block` 携带 authored cue 列表；`RebuildCueContract` 要求每个 cue 恰好一个显示单元 |
| 跨 cue event 按字符比例硬切 | 跨 cue event 在解析阶段 fail closed；不再使用 `shareOut()` |
| 人工/自动质量逻辑分叉 | 两者仍用同一 `SENTENCE` 质量指令；人工只追加“cue 是固定显示边界”的显示约束 |
| 缓存复用旧分页 | 缓存 identity 加入 authored 标记、cue 序列和契约版本；`read()` 重新验证 |
| 诊断无法判断格式/页契约 | `formatEvidence` 覆盖 JSON3/SRT；新增 cue summary、`AUTHORED_CUE` page basis |
| 引文标点差异整块丢弃 | 引文比较增加“去标点后仍逐字一致”的容错；仍拒绝改词/漏词 |

## 1. 具体修改

### 1.1 `RebuildPlanner.Block` 携带 cue 契约

`translation-core/.../RebuildPlanner.java`

- 新增 `Block.CueRange`：`index`、`from/to` token、`start/end` cue 窗口。
- `Block` 新增 `authored` 与 `cues`：
  - 自动块构造器保持 `authored=false,cues=[]`，旧测试/自动路径不变；
  - `planAuthored()` 用新构造器写入该块的全部 cue。
- 新增 `cueRanges(source,from,to)`：只从 `Word.cue` 分组，不重新分词。
- `Block.cue(index)` 用于契约校验。

### 1.2 新增 `RebuildCueContract`

`translation-core/.../RebuildCueContract.java`（新文件）

- `validate(source, block, events)`：
  - event 必须从块首开始、无空洞、按序覆盖到块尾；
  - 每个 event 必须完全落在一个 cue 内（`from.cue == to.cue`）；
  - 每个 cue 必须至少有一个 event，首 event 从 cue.from 开始、末 event 到 cue.to 结束；
  - 禁止跨 cue、跳过 cue、cue 内 event 空洞；违反抛
    `authored_cue_boundary` / `authored_cue_coverage` / `authored_cue_hole`。
- `units(...)`：
  - 一个 cue 一个 `RebuildDisplayGroups.Unit`；
  - 同一 cue 的多个 event 按顺序拼接为一个页文本；
  - Unit 的 `from/to/start/end` 来自 cue，而不是模型 event 的估计词时间；
  - 分隔符只处理标点/Latin 邻接，不再插入 U+200B 作为页切点。
- `addPayload(...)`：
  - 请求 payload 增加 `authored=true`、`display_cues`（每个 cue 的 token 范围、时间、精确源文）；
  - 调用 `RebuildGuidance.widenContext()`，人工块前后文从 24 token 扩到最多 600 token
    （`RebuildPlanner.context` 仍按 360 字符截断）。
- `VERSION = "authored-cue-v1"` 进入缓存 identity。

### 1.3 `RebuildProtocol` 解析阶段硬校验

`translation-core/.../RebuildProtocol.java`

- `parseInternal()` 在完整 parse 后调用 `RebuildCueContract.validate()`；prefix/流式 parse
  不校验，显示层会因不完整而暂不显示该块，避免先上屏错误分页。
- `payload()` 对 authored block 调用 `RebuildCueContract.addPayload()`；自动 payload 字节不变。
- `sameSource()`：先按原可见字符比较，再按“去掉空白和标点后的 characters”比较；
  `「」/“”`、`，/,`、补/漏句号不再导致整块 `source_quote_mismatch`；改词/漏词仍然失败。
- `RebuildReview.structuralRetry()` 增加三个 authored cue 错误码，触发结构重试。

### 1.4 请求提示词：同一套质量逻辑 + 固定显示边界

`translation-core/.../RebuildApi.java`、`RebuildGuidance.java`

- `RebuildApi.prompt(cfg,lang,context,block)` 新重载：
  - 自动源：与原来完全相同的 `SENTENCE` 质量指令；
  - 人工源：在同一 `SENTENCE` 之后追加
    `displayCueRule(block)`：“cue 是固定页边界；每个 event 必须在一个 cue 内；一个 cue
    可以有多个自然 event；禁止跨 cue 合并/移动文本”。
  - 不把 `SENTENCE` 替换成 `CUE`，不改变语义/数字/目标语言质量门禁。
- `RebuildGuidance.displayCueRule()` 列出每个 cue 的 token 范围；`widenContext()` 保留并被
  payload 调用。
- 删除未接线的 `authoredPrompt()`/`reviewCues()`/`cueDirective()` 旧实现，避免再次出现
  “写了但没调用”的死代码。

### 1.5 显示层：一个 cue 一个 Unit

`translation-core/.../RebuildController.java`

- `displayUnits()` 在 `authored=true` 时调用 `authoredUnits()`：
  - 使用 `RebuildCueContract.units()`；
  - 不再按 `plan.events` 逐 event 建页；
  - 删除 `shareOut()`、`cueSpans()`、`nearestClauseMark()`、`nearestWordBoundary()` 等
    “按字符比例伪造 cue 边界”的辅助；
  - 缓存 authored Unit 到 `DisplayLayout`，同 plan/geometry 不重复计算；
  - cue 契约异常时记 `REBUILD_CUE_CONTRACT_REJECTED` 并返回空，绝不产出伪造页。
- `Session` 新增 `authored`（在 source load 时一次性确定）；显示/渲染使用该值或
  `Block.authored`，不在每帧重复查询 catalog，避免同一会话内身份漂移。
- `REBUILD_UNIT_MODE` 增加 `units=` 与 `cues/events_per_cue`；
- `REBUILD_EVENTS_ACCEPTED` 对 authored 块增加 cue summary。

### 1.6 缓存 identity 与读取

`translation-core/.../RebuildCache.java`

- 新增 5 参数 `identity(..., boolean authored)`；旧 4 参数重载委托 `false`，自动路径 key
  不变。
- authored key 额外包含 `authored-cue-v1` 和每个 `Word.cue`；
- `read()` 仍走 `parseBound()`，因此缓存命中也会执行 cue 契约校验；不合约的旧缓存会被删除。

### 1.7 诊断与分页标签

- `RebuildSource.read()`：`formatEvidence` 对所有格式初始化自
  `parsed.timingCapabilities()`；JSON3/SRT 现在也会打印 `detected_fmt=json3/srt` 与
  `offset_segments`。VTT/XML 仍用各自更详细的证据覆盖。
- `RebuildPageLayout.unitPages()`：authored 单页的 `timingBasis` 从 `SOURCE_EVENT` 改为
  `AUTHORED_CUE`，诊断可直接确认“这一页是 cue 页”。

## 3. 回归测试

## 5. 仍未解决/边界

1. **cue 超过两行**：当前 `CaptionOverlayV2` 固定两行，`RebuildPageLayout` 对超过两行的
   authored cue 仍会按 cue 内子句切成多页（虽然页文本/时间不再由模型 event 直接决定）。
   这是“cue 原子性 vs 两行显示”的产品冲突，未在本轮强行改字号/行数；本轮诊断中的
   cue 均可两行内显示。
2. **流式预览**：authored 计划在完整覆盖 cue 之前不会显示部分页（`displayUnits` 返回空），
   等完整 plan；不会先上屏错误分页，但可能比自动源更晚出现。
3. **块 7 引文失败的原始响应仍未保留**；本轮通过 cue prompt、cue 范围 payload 和引文
   标点容错降低概率，但不能从现有诊断证明 request 39/40/42 的具体字符变化。
4. **翻译语义仍由供应商模型决定**；本轮没有新增语义裁判，只保证质量指令与自动源一致、
   cue 页不被模型事件切碎。
5. **未真机/未安装**：没有连接或写入手机；新 MPP 的实体安装、ABI/组合和真机 after 诊断
   仍待用户验证。
