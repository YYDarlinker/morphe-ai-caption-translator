# N43 语言记忆修复记录（2026-10-20）

本文件记录 `docs/N43-ROOT-CAUSE-20261019.md` 所述“冷启动自动选中简体中文 / 换视频仍简体中文”问题的实际修复。
上一轮 N44 只做了显示与跨语种校验，N43 的记忆链路当时**没有执行**；本轮补齐。

## 0. 一句话

目标语言现在只有一个权威：**本次启动中用户显式选择的目标**。YouTube 的自动/持久化译轨既不会成为目标，
也不会在换视频时被重新应用；每次译轨请求都按这个权威重写，冷启动则回到源字幕。

## 1. 根因（与 N43 对应）

1. 没有“未选择”状态：YouTube 持久化的 `zh-Hans` 自动译轨被 `CaptionChoice.select` 当成用户选择。
2. `onVideoId` 在换视频时 `CaptionChoice.reset()`，随后又把**上一个视频**的 selection 以
   `applySelection(track, true)` 重新应用，于是每个新视频都回到旧译轨。
3. `followNativeSelection` 的 automatic 分支会把任何自动译轨写进选择并启动引擎。
4. 请求路径没有目标权威：只依赖一次性的 `CaptionVideoHandoffV2`，而它的 `mayActivateAiTarget()` 前置条件
   在视频切换后为 false，handoff 基本是死代码。
5. 原生默认选择器在“没有记忆”时落回 YouTube 原生设置，即持久化的 `zh-Hans`；
   当目标不在该视频的 3 个译轨里时也没有克隆/改写。

## 2. 修复内容

### 2.1 每个译轨请求一个权威（`CaptionTargetPolicy`）

新增 `caption-shared/.../CaptionTargetPolicy.java`，在 `DeepSeekCaptionHook.rewriteUrl` 的前景译轨请求上调用：

| 状态 | 行为 |
|---|---|
| `decision < 0`（未选择） | 去掉 `tlang`，请求变源字幕；不启动付费翻译 |
| `decision == 0`（用户关） | 原样放行，由既有关闭逻辑处理 |
| `decision == 1` 且 `translated=false`（只用源字幕） | 去掉 `tlang` |
| `decision == 1` 且有目标 | `tlang` 重写为该目标，**不管**请求原本是哪个语言 |
| 原生 Auto-translate 菜单刚打开 | 放行，避免与用户正在进行的显式选择打架 |

`TargetLanguage.withoutTarget()` 只移除 `tlang`，保留 `v/lang/signature` 等全部签名参数。

### 2.2 自动默认永不成为选择

- `NativeCaptionBridge.followNativeSelection`：
  - automatic 且 `translated` → `NATIVE_SELECTION_IGNORED`，不写选择、不启动引擎；
  - automatic 且源字幕 → 只显示源字幕；
  - automatic 且本次启动已有显式目标 → 直接按目标激活（`NATIVE_REMEMBERED_ACTIVATED`），
    不再等原生默认轨道碰巧一致；
  - 只有 explicit 事件才写 `RememberedCaptionSelection` 与 `CaptionChoice`。
- `applySelection(track, false)` 对 `translate=true` 直接返回，杜绝自动译轨启动。
- `CaptionChoice` 只由显式选择写入；`automaticOff` 不再把 `chosen` 置真；
  新增 `targetLanguage()`（跨自动重置仍保留）、`markExplicitOff()` / `explicitOff()`。

### 2.3 换视频不再重置/重放旧轨道

`onVideoId` 只更新当前视频并记录诊断，**不** `CaptionChoice.reset()`，也**不**把上一视频的 selection
重新 `applySelection`。目标本身是 process-scoped（`RememberedCaptionSelection`），视频切换不改变它。

### 2.4 原生默认选择器：冷启动回源，目标缺失克隆

- `NativeCaptionBridge.sourceDefault(manager)`：返回该视频的源字幕轨（manual 优先，其次 ASR）。
- `NativeCaptionBridge.resolveRemembered(manager)`：目标不在该视频译轨列表时，用现有译轨
  `cloneTranslation` 克隆一个目标译轨（`LANGUAGE_REMEMBERED_CLONED`），而不是回退 `zh-Hans`。
- `NativeCaptionBridgePatch.hookRememberedDefault` 的 `defaultTrack` 前导改为：
  - 有记忆轨 → 返回记忆轨；
  - `decision < 0`（冷启动无选择）→ `sourceDefault`，失败才回原生设置；
  - `decision == 0`（用户关）→ 返回 null；
  - `decision == 1` 但记忆轨解析不到 → `sourceDefault`（再由请求策略映射目标）。
- `DeepSeekCaptionHookV2` 不再调用一次性 `CaptionVideoHandoffV2`；目标权威只在每请求策略里。

### 2.5 引擎开关/刷新不再“顺手”采纳自动译轨

- `refreshNativeTrack`：
  - 有显式目标 → 用记忆目标的**新鲜**原生轨 URL 激活；没有原生轨才用 `withCode(source, target)`；
  - 显式源字幕 → 只显示源；
  - 冷启动且自动默认是译轨 → `ENGINE_SNAPSHOT_DEFERRED`，不采纳；
  - 引擎关闭 → 不重选原生轨；
  - 原生重选使用记忆目标轨，而不是自动 selection 的轨道。
- `CaptionQuickToggle.setEngine(true)` 只清除“点按关闭”的 `userOff`，不清除 Auto-translate 菜单的显式 Off；
  `DeepSeekConfig.defaultTargetLanguage` 改读 `CaptionChoice.targetLanguage()`。

### 2.6 菜单选择请求本身就是确认

诊断显示冷启动后只有 `decision=-1`、`choice_known=false` 和 `NATIVE_SELECTION_IGNORED`，
没有 `origin=PREFERRED_TRACK` 的应用事件。原因是：用户第一次在 CC 菜单选择目标（尤其是选择
YouTube 已经持久化的同一语言）时，请求可能被冷启动策略剥掉，或者 YouTube 不再触发
“轨道变化”回调，于是 AI 永远等不到显式选择。

修复：
- `CaptionButtonController.nativeMenuRecentlyOpened()` 改为只看菜单窗口（预扫描也会置窗口），
  窗口由 12 s 延长到 30 s；手册菜单期间不再剥 `tlang`。
- `DeepSeekCaptionHook.rewriteUrl` 在“译轨请求 + 菜单窗口内”直接把请求的语言确认成
  `RememberedCaptionSelection` / `CaptionChoice`（`TARGET_CONFIRMED_BY_MENU_REQUEST`），
  即使 YouTube 没有单独的应用回调，第一次选择也会启动 AI 并成为本次启动的目标。
- AI 开启但还没有目标时，`CaptionQuickToggle` 提示 `choose_translation`，而不是静默 deferred。

## 4. 已知边界

- 真机尚未安装/连接；需要在手机上验证冷启动回到源字幕、长按选目标后换视频仍跟随该目标。
- 原生菜单的“勾选”项由 YouTube 模型决定；patch 的 `sourceDefault` 负责冷启动回源，
  但个别版本若初始化的 native 分支绕过 `defaultTrack`，菜单勾选可能仍显示旧项，而实际字幕/请求已按本源逻辑处理。
  诊断应看到 `TARGET_POLICY_APPLIED`、`NATIVE_REMEMBERED_ACTIVATED`、`LANGUAGE_REMEMBERED_CLONED`、
  `NATIVE_SELECTION_IGNORED`、`VIDEO_SWITCHED`。
- `partial` 缓存、字号按脚本标定仍按 N44-REPAIR 的设计决定未启用。
