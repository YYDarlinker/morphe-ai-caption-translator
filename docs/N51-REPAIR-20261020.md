# N51 — 人工 cue 边界不再阻止译文字幕显示（修复记录，2026-10-20）

本文件记录 `docs/N51-NO-TRANSLATION-ROOT-CAUSE-20261020.md` §7.2/§7.3 的实施。范围是当前工作树
（`dev/1.5.5-deepseek`）；产物是本地 **1.5.5 MPP**，没有签名、安装、推送或发布。

## 0. 修复摘要

| 问题 | 修复后的权威 |
|---|---|
| 模型事件跨过作者 cue → `authored_cue_boundary` 拒绝整块（N51 的 14.4 s“翻译中…”） | 跨 cue 只是**呈现事实**：`RebuildCueProjection` 把能精确铺满的 cue 作成 cue 页（第一层），其余事件各自成页（第二层），文本永不因边界被丢弃 |
| `RebuildSalvage` 丢弃跨 cue 事件、authored 还要求 `unitsPartial` 非空 | 与自动轨同一套逐事件 salvage；跨 cue 事件保留，交给投影 |
| 提示词“每条事件必须在一个 group 内” vs “每条事件必须成句”互斥 | 改为“**preferred** page boundaries；作者边界切开句子时，完整句子优先，事件可以跨边界”；`display_cues` 仍随请求发送，用于提高第一层命中率 |
| 一条 cue 失败即整块空白 | 页级发布：cue 页/事件页各自独立；`WAITING` 占位只覆盖还没有页的 cue |
| cue 之间的短空隙（<1 s）清屏（N51 的 1.63 s `source_gap`） | 投影把上一页延伸到下一页起点（与自动轨 `HOLD_MS` 一致） |
| 缓存可能复用旧提示词下的 authored 计划 | `RebuildCueContract.VERSION` 升到 `authored-cue-v3`（参与 `RebuildCache.identity`） |

N51 那块 4 cue / 14.5 s 的真实回复（3 条事件、107/107 token 覆盖）现在发布为 **3 个事件页**，
44.250–58.750 s 全程有译文；同一回复如果恰好与 cue 对齐，则仍是 **4 个 cue 页**（第一层不变）。

## 1. 具体修改

### 1.1 新增投影层

`translation-core/.../RebuildCueProjection.java`（新文件）

- `project(block, source, events, context)`：
  - **第一层**：对每个 authored cue group，若存在从 `group.from` 到 `group.to` 连续铺满的事件，
    合并为 cue 页（窗口 = cue 窗口），复用 `RebuildCueContract.unit()`；
  - **第二层**：所有未被第一层使用的事件各自成页，窗口 = 事件源 token 的 `start..end`，文本不切分、
    不复制、不丢弃；
  - 结果按源时间排序、不重叠；相邻页空隙 < `RebuildDisplayGroups.HOLD_MS`（1000 ms）时把上一页
    延伸到下一页起点，避免 cue 间空隙清屏；
  - 返回 `groups / cuePages / eventPages` 供诊断记录。
- 两层互斥性由“事件不重叠”保证：一个被精确铺满的 group 不可能与跨组事件共享 token，所以 cue 页与
  事件页不会重复显示同一段文本。

### 1.2 边界从“有效性”降为“呈现”

`RebuildCueContract.java`

- `VERSION` → `authored-cue-v3`；类注释改成“cue 是首选页，第二层保证显示”。
- `unit(...)` 从 `private` 改为包内可见，供投影复用。
- 删除只被 salvage 使用的 `withinOneGroup()`。
- `validate()` / `units()` / `unitsPartial()` / `partialUnits()` 保留为**严格第一层与测试工具**；
  生产接受路径不再调用它们（见 1.3）。

`RebuildProtocol.java`

- `parseInternal()` 不再调用 `RebuildCueContract.validate()`：事件跨 cue 不再是协议错误。
  逐事件内容校验（脚本、回声、空文本、时间、覆盖）与计划级校验保持不变。
- `parseBestEffort()` 注释更新：authored 与自动轨走同一 salvage；边界问题由投影回答。

`RebuildSalvage.java`

- 删除“事件跨 cue 就丢弃并记 `salvage_authored_cue_boundary`”的分支；
- 删除“authored 必须 `unitsPartial` 非空否则返回 null”的门槛；
- 其它逐事件规则（类型、覆盖、脚本/回声、时间、空洞）不变。

`RebuildReview.java`

- `structuralRetry()` 移除 `authored_cue_boundary` / `authored_cue_coverage` /
  `authored_cue_hole`；这三类不再出现，也不会再触发整块重发。

### 1.3 控制器接线与诊断

`RebuildController.java`

- `displayUnits()` 的 authored 分支改为 `RebuildCueProjection.project(...)`；删除旧的
  `authoredUnits()` / `authoredPartialUnits()`（流式前缀也用投影）。
- 新增诊断 `REBUILD_CUE_PROJECTION`：
  `session=..;block=..;groups=4;cue_pages=0;event_pages=3;events=3;partial=false`。
- `REBUILD_UNIT_MODE` 追加 `cue_pages=`、`event_pages=`，仍保留 `units=` 与 `events_per_group=`。
- 渲染/占位逻辑未改：`WAITING` 时仍按 `cue ∩ block` 显示“翻译中…”，但一旦计划可用，投影保证
  每个已翻译 token 都有页。

### 1.4 提示词

`RebuildGuidance.displayCueRule()`

```text
 Authored display groups are the preferred page boundaries. The display_cues field lists each
 group's first-last owned token ids. Prefer keeping every event inside one group, and use several
 natural events for a group when that keeps the sentence intact. When the author's boundary cuts
 a sentence, a complete sentence wins: an event may span the boundary. Cover every group's text.
```

`SENTENCE` 不变；`display_cues` 数据不变；pinned prompt/protocol 字面量不变
（`tools/verify_integration.py` 仍报 `prompt_and_protocol_literals_unchanged=true`）。

## 2. 测试

### 2.1 新增

`translation-core/src/test/.../N51AuthoredProjectionTest.java`（5 tests）

1. **真实 N51 回归**：用诊断里 4 条 cue 文本（token 数 18/30/36/23）和请求 89 的 3 条事件/译文；
   `parseBestEffort` 不再抛错，投影为 3 个事件页，每条 cue 的每个 token 恰好显示一次，页有序不重叠。
2. **对齐回复仍是 cue 页**：4 条事件逐 cue 铺满 → `cuePages=4, eventPages=0`，页窗 = cue 窗。
3. **500 ms cue 空隙不清屏**：上一页 end 被延伸到下一页 start。
4. **提示词**：包含 “preferred page boundaries” 与 “an event may span the boundary”，
   不再包含 “Every event must lie inside exactly one group”。
5. **任意切分性质测试**（300 轮随机）：随机 1–4 条 cue（3–12 token）、随机 1–6 条事件，断言
   每个 token 恰好出现在一页、页有序不重叠、每个事件都有文本、`cuePages + eventPages == units`。

`translation-core/src/test/.../N51AuthoredDisplayTest.java`（1 test，真实引擎 + MockWebServer）

  “cue0 + cue1 头 / cue1 尾 / cue2+cue3”三条跨边界事件；
- 断言 0.5 s、2 s、3 s、4.5 s、6.5 s 各位置都有译文；跨页过渡没有任何 `hide`（无空白）；
  计划到达后不再出现“翻译中…”。
