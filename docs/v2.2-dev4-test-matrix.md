# v2.2 cost/quality pass — device test matrix

This checkpoint documents the completed dev4 cost/quality plan currently implemented on the `dev` branch. It is intentionally documentation-only so republishing the already-built implementation does not alter runtime behavior.

## Runtime policy under test

- Cold-start Priority keeps the full semantic observation window but uses a smaller productive core and returns only the complete unit covering the playback focus. It must never shorten an incomplete sentence merely to improve first-caption latency.
- Background inventory uses 30 s low-water / 55 s high-water hysteresis while retaining a 60 s observation horizon and the 9 s urgent gap-rescue path.
- Background results that cover only READY atoms cannot rewrite an already-approved canonical translation; mixed READY + UNRESOLVED ranges may still heal a semantic seam.
- Semantic API payloads use the compact ordered atom protocol while preserving source text and timing information. Stable source/context fields precede volatile scheduler fields to improve prefix-cache reuse.
- Display slicing gets one normal AI attempt. If it does not produce a safe multi-slice result, the existing deterministic local fallback is used without changing canonical translation text.

## Regression requirements

A candidate is not acceptable if it introduces subtitle gaps, degrades translation completeness/accuracy versus the v2.1/dev1 baseline, breaks player/miniplayer/fullscreen lifecycle behavior, or materially worsens first-caption latency.

## Test procedure

1. Clear translated-caption cache and token diagnostics.
2. Use the same English source video used for the previous dev1–dev3 comparisons where possible.
3. Play continuously for roughly five minutes without seeking for the primary sample.
4. Separately test seek, miniplayer return, portrait/landscape transition, CC on/off, and a fast-speaking video.
5. Capture the complete Token Cost Audit plus subjective notes on first-caption delay, translation quality, sentence/display cadence, and any subtitle gaps.

## Metrics to compare

- FIRST_AI_READY latency
- tokens per watched minute
- estimated RMB cost per watched minute
- prompt cache hit/miss tokens and hit rate
- Priority / Background / Display request and token split
- Background logical requests per watched minute
- context exposure ratio
- ZERO_UNIT_WINDOW count
- DISPLAY_SLICE_LOCAL_FALLBACK / DISPLAY_SLICE_SKIPPED frequency
- LEDGER_SHADOW_MERGE frequency

The optimization goal is real cost reduction with preserved or improved user-visible quality, not merely a lower total-token counter.
