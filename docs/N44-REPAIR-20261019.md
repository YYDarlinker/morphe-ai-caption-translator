# N44 — 全语种显示保证：实施与验证记录（2026-10-19，P1/P2/P3 + P4）

本文件记录在 `docs/N44-ALL-LANGUAGES-DESIGN-20261019.md` 之后实施的 P1/P2/P3 与 P4 脚本适配改动。
范围：`translation-core`、`caption-shared`、测试、`docs/core-provenance.json`、`tools/verify_integration.py`。
没有签名、安装、推送或发布；没有连接或写入手机。

## 0. 一句话

**把“失败单元”从 block 降到 segment，把“质量建议”从硬门禁降为 advisory，把“未知语种”从静默
GENERIC 改为可用 profile。** 忠实译文不再因为数字/引文/单位/文字系统的差异而整块消失；
一个坏 event 只留下它自己的缺口，而不是吃掉整块；块级重试有上限；每个缺口在屏幕上有一个
中性标记（`…`），不再是无法解释的空白。

## 1. 改了什么

### 1.1 部分发布（`RebuildProtocol` + 新 `RebuildSalvage`）

- 新增 `RebuildProtocol.parseBestEffort()`：先走严格 `parseBound()`；失败时调用
  `RebuildSalvage.parse()`。严格路径、缓存读取、既有测试保持不变。
- `RebuildSalvage` 逐 event 做 identity 检查：
  - 结构性无效（非对象、ID 类型/越界/重叠/倒序）→ 丢弃该 event，记 issue；
  - 空文本：非语音允许，语音则丢弃并记洞；
  - 协议泄漏、目标文字系统不匹配、源文回声、信息坍缩、时间重叠 → 丢弃并记洞；
  - 数字冲突、语义锚点、句末依赖、事件内停顿 → **只记 advisory，发布**；
  - 引文差异 → **只记 `source_quote_hint`，发布**（`from/to` 是权威身份）。
- 覆盖不足（少于 1/3 token）或没有任何可用 event → 返回 null，保留严格路径的失败，
  交给有界重试。
- `Plan` 新增 `partial` 与 `holes`（显式未翻译 token 范围）；`withLayoutReview()` 与
  `prefer()` 都保留这两个字段，完整 plan 永远优先于 salvage plan。
- 人工轨（authored）也走 salvage，但只发布完整 cue group（见 1.6）；半覆盖 group 不以截断页出现。

### 1.2 数值：从门禁改为观察 + 词法修复

- `RebuildProtocol.parseInternal()` 不再因 `numeric_substitution` 抛异常，改为
  `numeric_observation`（`repair=false`），文本照常发布。
- `RebuildNumbers`：
  - 数字 token 不再带符号匹配；负号只在 `-` 位于行首/空白/括号/运算符之后时生效
    （`Т-14`、`Τ-14`、`ت-14`、`टी-14`、`티-14` 都读成 `14`，不再是 `-14`）；
  - 数字紧邻 CJK 也可见（`约4.5倍`、`有25艘`），不再被 Unicode 边界吞掉；
  - 阿拉伯 U+066B（小数）/U+066C（千位）映射修正（此前反了）；
  - 全角连字符/数学减号归一；
  - 量级词增加 `억`、`करोड़`、`लाख`、`millones/millions/milioni/milhões/Millionen`。
- 严格路径中的数值冲突同样只记 `numeric_observation`；`RebuildNumbers.compare()` 本身仍能
  识别真正的值冲突（供诊断/质量证据使用）。

### 1.3 引文、Unicode、目标文字

- salvage 不再要求 `source` 字段逐字匹配；ID 有效就接受。严格路径的引文校验保持不变
  （缓存身份仍要求完整、可复核的回复）。
- NFD/组合符号、bidi 控制符等不再让整块消失（ID 优先）。
- 目标文字系统（`validateTarget`）与回声检测仍在，但**只丢弃该 event**，不丢块。

### 1.4 控制器：有界重试、覆盖诊断、缺口标记

- 部分 plan 立即发布；`states=READY`，不再触发修复重试；partial 不写缓存。
- 慢重试新增上限 `MAX_SLOW_RETRIES=3`：同一块连续三次确定性失败后置 `FAILED` 并记
  `REBUILD_BLOCK_ABANDONED`，不再无限付费重试。
- 新增诊断：
  - `REBUILD_PARTIAL_ACCEPTED`（块、事件数、洞数、覆盖 token）；
  - `REBUILD_COVERAGE`（洞的 token 范围、原因）；
  - `REBUILD_COVERAGE_REPORT`（会话结束/停止时：complete/partial/failed/holes）；
  - `LANGUAGE_PROFILE`（target、profile、named/generic、脚本、方向、cps/cpl、行计数）。
- 部分 plan 的洞在 `render()` 中显示中性标记 `…`（`id=unavailable:...`），不是源文，
  也不再是无解释的空白。普通估算空隙（非洞）仍按静默处理。

### 1.5 语种属性（P4）

- `CaptionScript.compact` 移除 HANGUL：韩语按空格分隔；韩语合并事件不再丢空格，
  U+200B 不再作为韩语词内页缝。
- `CaptionLanguageProfile.fromCode("zh")` → `zh-Hans`（不再丢 9 cps/16 cpl/CJK 行计数）；
  `zh-Latn` 等异常脚本仍为 GENERIC。
- 未知但有 RTL 脚本（Arab/Hebr/Thaana/Syriac/Nko/Adlam）的 code → 合成 `generic-rtl`
  （RTL，17/42），不再给 LTR 契约。
- 未知但有 CJK/Hangul/Devanagari 脚本的 code → 合成 `generic-cjk`（9/16）、
  `generic-hangul`（12/16）、`generic-devanagari`（22/42），不再一律 17/42。
- 句读表补齐阿拉伯 `؟`、乌尔都 `۔`、天城文 `।/॥`、希伯来 `׃`、埃塞俄比亚 `።`：
  `RebuildSource.terminal`、`SourceReadingWindows.CLAUSE`、`RebuildPageLayout.weight`、
  `RebuildDisplayGroups.TERMINAL`、`RebuildReview.endsSentence` 同步。
- `SourceReadingWindows` 的“宽脚本”判定补 Lao/Khmer/Myanmar。
- `CaptionRenderSpec` 的注释同步修正。

### 1.6 人工 cue 的 partial（authored）

- `RebuildCueContract.unitsPartial()`：只发布**完整**的 cue group，缺失或半覆盖的 group 跳过；
  半覆盖的 cue 不会以截断页出现。
- authored block 也走 salvage：event 必须落在一个 cue group 内；至少一个完整 group 才发布，
  否则保留严格失败。`RebuildController.authoredUnits()` 对 partial plan 使用 `unitsPartial()`。

### 1.7 缺口子请求、FAILED 标记与覆盖诊断（P3/P5）

- 部分 plan 接受后，如果仍有洞且块尚未播完、该块还没有补过：对**最大的洞单独发一次**
  sub-request（`holeBlock()`：只覆盖该 token 范围；authored 只对完整 cue group），
  返回结果经 `RebuildReview.mergeInto()` 只补新范围、不替换屏幕上已有的文本。
  失败/无改进只保留洞，不导致父块失败；每块最多一次。
- 块在慢重试上限后置 `FAILED`，或供应商 `content_filter` 终止时，`render()` 在该块的
  源 cue 窗口内显示中性 `…`（`unavailable:failed:...`），不再是无解释空白；永不显示源文。
- `REBUILD_HOLE_FILLED` / `REBUILD_HOLE_FAILED` 记录子请求结果；`REBUILD_PRESENTATION`
  新增 `reading_cps` 与 `page_density_over_limit`（P5 页密度诊断）。
- `LANGUAGE_TRACKS_AVAILABLE` 记录播放器运行时给出的自动翻译 code 集合（去重、上限 160）。

## 3. 行为变化与取舍（需要知道）

1. **数字冲突不再阻断显示**：译文里数字与源不一致时，字幕仍显示，诊断记
   `numeric_observation`。这是“先让观众看到句子”的产品取舍；若以后要求数字优先，可对
   单值 quantity 冲突做该 event 的定向重试，而不丢块。
2. **引文不再是身份**：ID 有效即接受；引文只用于 ID 无效时的重对齐。缓存仍然严格要求
   完整可复核的回复。
3. **洞是显式的**：`Plan.holes` 记录未翻译 token 范围；屏幕用 `…` 标记。它不是译文，
   但也不是无解释空白。
4. **块会被放弃**：同一块连续 3 次慢重试仍无可用 plan → `FAILED` + `REBUILD_BLOCK_ABANDONED`；
   该块的源 cue 窗口显示中性 `…`，不是源文，也不是无解释空白。
5. **人工轨只发布完整 cue group**：半覆盖的 cue 不会以截断页出现，缺失 group 成为洞。

- **语言注册表**：P4 已覆盖脚本回退/句读/宽脚本/运行时 `LANGUAGE_TRACKS_AVAILABLE`；
  仍有字号按脚本标定（需真机视觉验收）与个别 RTL 标点细节。
- **P5 页密度**：已加 `reading_cps`/`page_density_over_limit` 诊断；页切分仍不按密度强制
  （切分不改变总 cps），未设发布门禁阈值。
- **真机复验**：未安装、未连接手机。安装新 MPP 后，诊断应出现
  `LANGUAGE_PROFILE`、`REBUILD_PARTIAL_ACCEPTED`、`REBUILD_COVERAGE`、
  `REBUILD_COVERAGE_REPORT`、`REBUILD_BLOCK_ABANDONED`、`REBUILD_HOLE_FILLED`、
  `LANGUAGE_TRACKS_AVAILABLE`；`translation_failed` 帧应显著减少。
- 已知边界：salvage 覆盖自动源与人工源（人工只发布完整 cue group）；覆盖不足 1/3 仍按失败
  重试（人工至少一个完整 group）；数字/语义仍是 advisory，不代表译文语义正确。
