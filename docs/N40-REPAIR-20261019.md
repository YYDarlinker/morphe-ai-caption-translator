# N40 — 四项问题修复与回归记录（2026-10-19）

本文件记录在 `docs/N40-ROOT-CAUSE-20261019.md` 根因调查之后实施的修复。范围是当前工作树
`dev/1.5.4-deepseek`；没有签名、安装、推送或发布。

## 0. 修复摘要

| 问题 | 修复后的权威 |
|---|---|
| 语种记忆回到简体 | 记忆优先于原生默认；自动默认不能覆盖用户选择；克隆轨保留真实 code |
| 繁体标签冗余 | 中文变体统一走应用资源标签；原生冗余标签在列表/元数据中重标注 |
| 自动源翻页漂移 | XML `<s t>` 进入 `RebuildSource`；粗计时也尝试 ASR 参照；页面时间优先落在真实语音边界 |
| 人工源质量 | 请求块可跨 cue 成句，事件仍严格按 cue；所有语言对做目标文字校验 |

## 1. 语种记忆

### 1.1 `CaptionVideoHandoffV2` 改为记忆优先

`application-host/.../CaptionVideoHandoffV2.java`

- pending 的武装条件：`memoryInstalled() && (RememberedCaptionSelection.decision() == 1 || CaptionChoice.isOn())`。
- `restoreForNextVideo()` 的目标：
  - 有显式记忆且 `translated`：`RememberedCaptionSelection.language()`；
  - 记忆是 source-only：不改写源请求（不把 source-only 变成付费翻译）；
  - 没有记忆：退回 `DeepSeekConfig.defaultTargetLanguage()`（冷启动/无 Remember 补丁）。
- 诊断事件 `VIDEO_DEFAULT_AI_RESTORED` 的文案改为 “Remembered caption target restored…”。

这保证：即使用户当前 `CaptionChoice` 被原生默认污染成 `zh-Hans`，下一个视频仍按记忆的 `en` 改写
timed-text 目标。

### 1.2 自动原生默认不再覆盖用户选择

`application-host/.../NativeCaptionBridge.java` `followNativeSelection()`

- 当事件不是显式 `PREFERRED_TRACK`、不是 Off，且 `CaptionChoice` 有非空、非 user-off 的选择：
  - 若原生默认与当前选择不同：已有可见会话时**忽略**该事件（记 `NATIVE_SELECTION_IGNORED`）；
  - 尚无可见会话（新视频）时，用当前选择的源 URL + 目标 code **重新激活**（记
    `NATIVE_SELECTION_REPLACED`），而不是启动原生默认。
- `applySelection()` 的 remember 条件保留自动重置的恢复能力：
  `explicit || (!off && (!CaptionChoice.known() || !CaptionChoice.userOff()))`。
- `prewarmSource()` 改为记忆优先，避免提前用被污染的 `CaptionChoice` 预取错误目标。

### 1.3 克隆轨 identity

`patches/.../NativeCaptionBridgePatch.kt` `bindCloneTranslation`：

```smali
move-object v1, p1
invoke-virtual {v0, v1}, languageSetter
```

不再把所有新增语言写成 `zh-Hans`。这样 `CaptionChoice`、`RememberedCaptionSelection`、
`resolveRemembered()` 和菜单去重都看到真实 code。

### 1.4 空 code 不再默认简体

`caption-shared/.../TargetLanguage.java`

- `fromCode("")` 返回 `null`；`withCode(url, "")` 原样返回，不再追加 `tlang=`。
- 调用方（prewarm、`CaptionLanguageContext.observe`、`RebuildController`）已按 null 处理。

## 2. 繁体标签

### 2.1 一个应用标签

`ui/.../LanguageMenuOrder.java`

- `label("zh-Hant")` 改用应用资源 `cap_language_zh_hant`（例如 `中文（繁体）` /
  `中文（繁體）` / `Chinese (Traditional)`），不再走 ICU `中文 (繁体)`。
- `label("zh-Hans")` 同样优先应用资源；保留原 ICU/硬编码 fallback。
- 只有精确 `zh-Hant` 走新标签；`zh-TW`/`zh-HK` 仍保留地区标签，避免把所有繁体地区名都改掉。

`NativeCaptionBridge.translationLabel()` 对中文变体强制使用 `LanguageMenuOrder.label(canonical)`，
不再优先 YouTube 原生标签。

### 2.2 原生冗余标签重标注

不用改 YouTube 原生对象的所有字段；只替换显示名：

- 新增 bridge stub `relabelTranslation(track, code)`。patch 用 track builder copy constructor 复制原生
  track，**只改 display 字段**，保留 language/url/vss。
- `augmentTranslations()` 对已存在的选中中文条目：仅当原生标签是冗余形式（含
  `繁体中文`/`繁體中文`，或简体的 `简体中文`/`簡體中文`）时，原位替换为 relabeled copy，记
  `LANGUAGE_MENU_RELABELED`；URL/vss 不变。
- `CaptionLanguageMetadata.addSimplified()` 对元数据中已存在的选中中文条目做同一判定和 relabel：
  只改 field 2.4（display），保留原 code（如 `zh-TW`）及其余字节；记入同一条路径。

因此 `中文（繁体中文）` 被归一成应用标签；`中文（台湾）` 这类不是冗余脚本名的标签不强行改动。

## 3. 自动源翻页

### 3.1 XML/srv3 计时进入规划器

`translation-core/.../RebuildSource.read()`

- 当 payload 是 XML，或 `CaptionDocument.rawFragments()` 带 native offset 时，使用每个
  `RawFragment` 的文本/起止/`nativeOffset` 构建 span，而不是只读整条 `<p>` cue。
- XML 的 `<s t>` 内多词片段只把**第一个 token** 标成 `NATIVE`（claimFirst）；内层 token 仍严格标
  `ESTIMATED`。JSON3/VTT 原来的规则保持不变，避免把插值伪装成 native。
- `formatEvidence` 写 `CaptionDocument.timingCapabilities()`，下次诊断可直接看到
  `detected_fmt=xml;raw_fragments=…;offset_segments=…`。

### 3.2 粗计时也尝试 ASR 参照

`RebuildController.load()`

- 手工轨（`authored`）保留 cue 级时间，不额外下载参照。
- 自动轨只要 `nativeWordCount() < words.size()` 就尝试 `alignedToReference()`；不再要求
  `nativeWordCount() > 0`。全部 native 时才跳过并记 `reason=all_words_native`。

### 3.3 页面时间落到真实语音边界

- `RebuildController.pageAnchors()` 从当前显示单元（`Unit.from/to`）的源词收集：
  - 词间停顿 ≥ 220 ms；
  - 以分句标点结尾的词；
  - 过滤掉距单元首尾不足 `MIN_PAGE_MS` 的边界；最多 64 个。
- 通过 `TranslationOutput.showEvent(..., long[] sourceAnchors)` 传到
  `CaptionOverlay → CaptionActions.displayPages → TranslationPresentation →
  RebuildPageLayout.plan/unitPages/allocate`。
- `allocate()` 在有足够 anchors 时按页序取真实边界，单调性不满足则回退阅读权重；没有 anchors 时行为
  与之前一致。2 页取中位 anchor，3 页以上按首尾均匀取 anchor。使用 anchors 的页标记为
  `page_basis=SOURCE_PAUSE_ANCHOR`，便于真机诊断确认。
- `CaptionOverlay` 的页面缓存 key 包含 anchors，避免同一文本在 anchors 变化时复用旧页。

## 4. 人工源翻译质量

### 4.1 请求块跨 cue，事件仍按 cue

`translation-core/.../RebuildPlanner.planAuthored()`

- 连续 cue 可以组成一个请求块，直到：
  - 上一 cue 的 `boundary()`（句末/硬 gap/speaker change）；
  - 下一 cue 前有 hard break；
  - 4 个 cue、600 字符、20 秒上限。
- 每个 block 仍由 `RebuildGuidance.CUE` 要求“一个 cue 一个 event”，`reviewCues()` 继续拒绝跨 cue
  event。因此显示边界仍是作者的分行，模型却能看到完整句子上下文。
- 真实 `FzRyrjFmZSQ.ja.vtt` 探针从 400 个块降为 **103** 个块（400 cue 保持不变）。

### 4.2 所有语言对的目标文字校验

`translation-core/.../RebuildSemantics.validateTarget()`，在 `RebuildProtocol` 每个 event 上无条件调用：

- 目标 `zh`：禁止假名/谚文；源有 >1 词且译文 >4 个字母却无汉字时拒绝。
- 目标 `ja`：禁止谚文；无假名/汉字且源有 >1 词时拒绝。
- 目标 `ko`：禁止假名；无谚文/汉字且源有 >1 词时拒绝。
- 跨语言完全重复源文（可见字符相同、源 >12 字符）拒绝为 `untranslated_source`。
- 原来的英译中数字/装备锚点检查保持不变；新检查覆盖此前完全跳过的日译中等组合。

拒绝原因：`target_language_mismatch` / `untranslated_source`；错误进入既有结构重试/修复路径。

## 7. 仍待真机/安装包验证

1. **安装包代码身份**：本轮生成了 MPP，但没有把新 MPP 装到实体手机。真机诊断应确认：
   - `NATIVE_SELECTION_IGNORED` / `NATIVE_SELECTION_REPLACED` 出现于自动默认；
   - `LANGUAGE_MENU_RELABELED` 出现且菜单显示应用标签；
   - `REBUILD_SOURCE_READY` 的 `measured_or_aligned` 不再恒为 0；
   - `page_basis`/页面时间是否落在 anchors。
2. **原生标签形态**：只归一含 `繁体中文` 的冗余标签；若 YouTube 实际使用另一种写法，需用真机
   `displayName` 证据扩展判定。
3. **非中文目标页面**：`CaptionLanguagePager` 的 fallback/choose 路径仍主要用阅读权重；本轮 anchors
   接入 `unitPages` 主路径。若真机仍有非中文目标的页漂移，应把 anchors 继续传入 `choose/fallback`。
4. **源格式**：运行时 payload 正文未导出；XML 修复针对 `CaptionDocument` 已识别的 `<s>`。若实际是
   无内嵌时间的 VTT，仍会退化为 cue 估计，需要真机 `detected_fmt` 确认。
5. **语义质量**：`validateTarget` 是脚本/回声护栏，不是完整语义裁判；模型残余错译仍需人工验收。
6. **真机 ABI/组合**：MPP 已构建，但尚未做实体 APK 安装/运行组合；`relabelTranslation` 的新 stub 和
   XML 分支需在 YouTube 21.20.405 真机上验证。
